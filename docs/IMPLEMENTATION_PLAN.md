# Plant Doctor 実行計画

## 目的

Plant Doctorは、葉温・気温湿度・照度・土壌水分を装置単体で取得し、植物ごとの
平常状態からのずれをストレス指標として表示する。乾燥時には安全に給水し、その後の
土壌水分応答から給水系の異常も検出する。企画の詳細はProtoPediaの
「植物ストレスを診て水やりするエッジAIテラリウム」を正とする。

本計画では、各段階の「コードがある」ことではなく、実機で確認できる完了条件を採用する。

## 現在地

- `PlantDoctor`：電源自己保持、10 msタイマ、LED、LCD、スイッチ、エラー状態まで実装済み。
- `SensorDiagnostic`：SEN0206、SEN0385、SEN0228、SEN0193、SEN0204の個別値を確認する独立ファームウェアを実装済み。
- 本体の`SensorManager`、`PlantAi`、`PumpControl`、`PlantLog`は、インターフェースまたはスタブ段階。
- Solist-AIの学習・推論ライブラリは現CMakeビルドに未接続。
- I2CのLCDとSEN0206/SEN0385/SEN0228はCN3上の同一バスを共有する。

## 実施順序

### M0: センサ診断とI2Cバスの安定化

目的は、全センサを接続しても診断ファームウェアが停止せず、各センサの成否を区別して
表示・デバッグできる状態にすること。

- SEN0385未接続時の`NACK`は故障ではなく「未接続」として扱う。
- LCDと各I2Cセンサを共通のバス管理層へまとめ、通信失敗時にSTOP、周辺回路再初期化、再試行を行う。
- 長い通信待ちや1台の失敗が、スイッチ・LED・LCD更新全体を止めないよう、タイムアウトを短くし、測定を状態機械化する。
- LCD更新失敗後は、一定間隔で再初期化を試みる。LCDが使えない間も、LEDとデバッガのスナップショットで状態を確認できるようにする。
- 診断の全構造体を毎回初期化し、失敗測定で未初期化の値を表示・保存しない。

完了条件：SEN0385とSEN0204の有無を変えても、電源投入10回と30分連続測定でメインループが継続する。各未接続センサは`NACK`、接続済みセンサは値または具体的な通信エラーとして識別できる。

### M1: センサドライバを本体へ統合

診断専用コードを検証後に共通化し、通常の`PlantDoctor`から非ブロッキングに取得する。

- `SensorManager`へ、センサ値、取得時刻、通信状態、有効期限を持つスナップショットを追加する。
- SEN0206（葉温）、SEN0385（気温・湿度）、SEN0228（照度）、SEN0193（土壌水分）、SEN0204（液面）を統合する。
- LCDは値をページ切替で表示し、未接続・古い値・CRC失敗を正常値として扱わない。
- 土壌水分は、最初は鉢ごとの相対値として扱う。水分率への変換は校正後に行う。

完了条件：通常ファームウェアで全接続センサの値と個別状態が表示され、センサの抜き差し後も他センサとUIが継続する。

### M2: 校正、時刻、ログ、特徴量

AIに渡すデータの意味を固定する段階。

- SEN0193について乾燥時・十分に湿った時の値を記録し、鉢ごとの校正値を設定として保存する。
- RTCを有効化し、測定値・状態・給水イベントを時刻付き固定長レコードにする。
- FRAMの接続を確認後、リングバッファとしてログを保存する。未接続時はRAMの最小バッファで動作する。
- 土壌水分の移動平均と変化速度、葉温－気温、葉温変化速度、照度、湿度、前回給水からの時間を計算する。

完了条件：昼夜を含む24時間の時系列と給水イベントを取得でき、再起動・欠測・センサ異常が記録から判別できる。

### M3: 手動給水と安全制御

自動判定の前に、ポンプを安全に、かつ結果を測りながら動かせるようにする。

- OUT0を明示的にOFFへ初期化し、起動直後、リセット、ウォッチドッグ復帰、センサ異常時は必ずポンプOFFとする。
- 手動給水はLCD/スイッチから短時間だけ要求できるようにする。
- 一回の最大ON時間、最小給水間隔、一定時間内の最大給水回数を設定する。
- 液面なし、土壌水分が無効、測定が古い、または応答評価中は給水を拒否する。
- 外部12Vとポンプを接続する前に、SSR出力とDFR0457信号をテスターで確認する。

完了条件：ポンプ未接続でSSR動作を確認後、水系を監視した状態で短時間給水を行える。異常時や連打時にポンプがONにならない。

### M4: 給水後の応答評価

企画の「水をやった結果まで診る」を、AI導入前の説明可能なルールで実現する。

- 給水前の土壌水分、給水時間、給水直後・遅延後の水分増加量、安定化時間を記録する。
- 増加量不足を`WATERING_RESPONSE_FAILED`として扱い、連続再給水せず警告へ遷移する。
- 液面情報は、水切れ候補の優先度を上げる補助情報にする。

完了条件：通常給水と、タンク空・ホース外れ相当の「土壌水分が回復しない」条件を、表示とログで区別できる。

### M5: オンデバイス学習とストレス表示

Solist-AI導入前に、SDK・GCC・必要RAM・モデル保存方式を最小プログラムで検証する。

- 先行テーマは「給水後の土壌水分応答の異常検知」とする。
- 次に、日周を含む複数特徴量から植物ごとの平常状態を学習する。
- 学習未完了、通信異常、疑似入力、すでに異常と判断した期間のデータは正常学習に混ぜない。
- 0～100の値は「平常状態からのずれ」と定義し、病名や健康度を断定しない。
- AIの異常度のみで給水せず、土壌水分・液面・安全上限と組み合わせて判断する。

完了条件：未学習時は`LEARNING`を表示し、学習済みデータと別期間の記録で、固定しきい値方式との比較ができる。

### M6: 展示・連続運転

- LCDのページ表示を、`Stress`、状態、葉温－気温、土壌傾向、センサ異常、給水結果へ整理する。
- 熱変化、乾燥・給水、給水失敗、センサ未接続を短時間で再現するデモモードを追加する。
- 通常モードとデモモードを明確に区別し、デモモードでも給水安全上限は無効化しない。

完了条件：通常診断、熱ストレス傾向、乾燥給水、給水失敗、センサ異常の各デモを再現でき、連続運転時にログと表示が破綻しない。

## 直近の作業

次の実装対象はM0である。まずSEN0385未接続時の`NACK`を想定状態として明示し、LCDがランダムなページで失敗する原因をI2Cのエラー処理・LCD復帰・未初期化データの観点から修正する。その実機確認後、M1へ進む。

## 配置方針

- ML63Q2557固有のビルド設定、ドライバ、アプリは`firmware/ml63q2557/`に置く。
- 今後別MCUを追加する場合は`firmware/<mcu>/`を追加し、アプリの仕様・ログ形式・テスト基準は必要になってから共通化する。
- README以外の設計・配線・試験・本計画は`docs/`に置く。
